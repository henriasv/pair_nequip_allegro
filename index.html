Multi-GPU pair_nequip

Native multi-rank NequIP inference in LAMMPS via a per-layer ghost-feature exchange compiled into the AOTInductor artifact. This page holds everything needed to evaluate the contribution: the design and its implementation, the exhaustive compatibility audit, the validation record, and the benchmarks with their exact environments.

1Scope and how to review

Upstream pair_style nequip is restricted to one MPI rank: a message-passing model needs features of atoms owned by neighboring ranks at every interaction layer, not just a geometric halo at the input. This work removes the restriction natively — the compiled model itself performs a distributed halo exchange of node features between layers — so NequIP (including OAM-family foundation models) runs LAMMPS-domain-decomposed across GPUs with the standard pair_style machinery: no server processes, no Python in the MD loop.

2Design

The route was chosen against a fat N-layer input halo (receptive field ~N·rcut makes ghost shells — and redundant compute — explode with layer count) and against the existing ML-IAP coupling (eager-only, see §3.1). Per-layer exchange keeps each rank's ghost shell at one cutoff and moves features instead of recomputing them.

Compiling for multi-GPU is one command — the target implies the ghost-exchange modifier and stamps metadata the pair style cross-checks at load:

nequip-compile model.nequip.zip model.nequip.pt2 \
    --mode aotinductor --target pair_nequip_multirank --device cuda \
    --modifiers enable_OpenEquivariance     # optional acceleration

3Implementation

3.1 The exchange is a custom op with no LAMMPS handle in its signature

The existing ML-IAP ghost exchange is a Python autograd.Function that calls methods on a lmp_data object — which is exactly what cannot survive AOTInductor (the .pt2 runs in C++ with no interpreter). Here the exchange is a registered Torch operator whose schema carries only the tensor. The LAMMPS process defines the real implementation; the live pair instance is reached through a thread_local pointer to a minimal abstract bridge, armed only for the duration of a model call (pair_nequip_allegro.cpp):

TORCH_LIBRARY(nequip_lammps, m) {
  m.def("ghost_exchange(Tensor node_features) -> Tensor");
  m.def("ghost_exchange_reverse(Tensor grad_features) -> Tensor");
}
TORCH_LIBRARY_IMPL(nequip_lammps, CompositeExplicitAutograd, m) {
  m.impl("ghost_exchange", &ghost_exchange_impl);          // -> bridge, or identity
  m.impl("ghost_exchange_reverse", &ghost_exchange_reverse_impl);
}

With no bridge armed — ASE, export tracing, single rank — the ops are the identity, which is also the traced behavior. On the Python side the same schema is registered with identity implementations and ghost_exchange_reverse wired in as the autograd rule (nequip/nn/_ghost_exchange_pair.py), so the transpose is traced into the compiled backward. There is no double-registration: compile process and LAMMPS process are separate.

3.2 Truncate-to-nlocal through a backed dynamic dimension

Per-node work should run on owned atoms only, but the owned count must not enter the graph as a tensor value (.item() → unbacked symint → export guard failures). Instead a marker input num_local_nodes_marker of shape (nlocal,) carries the count as its dimension (nequip/nn/interaction_block.py):

elif "num_local_nodes_marker" in data:
    num_local_nodes = data["num_local_nodes_marker"].shape[0]  # backed symint
...
x = self.tp_scatter(...)   # over all ntotal rows (feature halo just refreshed)
x = x[:num_local_nodes]    # every per-node op below runs owned-only

Before each exchange the owned block is re-expanded to ntotal with slice_scatter — deliberately not cat with a zeros block, which triggers 0/1-size specialization during export and bakes in either nghost ≥ 1 or nghost ≤ 0. The export example uses nghost > 0 so the nlocal and node dims stay independent; the only deferred assert is nlocal ≤ ntotal, satisfiable at both ends. Energy reduction masks ghost rows with a guard-free elementwise comparison, so forces (its gradient) are owned-consistent too.

3.3 Two bridge implementations: host-staged and device-resident

Plain pair_style nequip stages [ntotal, F] through host double buffers and Comm::forward_comm(this, F) / reverse_comm(this, F) via the standard pair pack/unpack callbacks. pair_style nequip/kk (new instantiation PairAllegroKokkos<true>, now deriving from KokkosBase) keeps features on the GPU: pack/unpack kernels index the live tensor's device pointer by the device sendlist, and the exchange runs through CommKokkos::*_comm_device (GPU-aware MPI on device buffers):

Kokkos::parallel_for("nequip:pack_fwd", RangePolicy<DeviceType>(0, n * F),
    KOKKOS_LAMBDA(const int s) {
      const int i = s / F, c = s % F;
      buf(s) = p[(long) idx(i) * F + c];          // rows of the live feature tensor
    });
...
Kokkos::atomic_add(&p[(long) idx(i) * F + c], buf(s));  // reverse: accumulate to owners

After the reverse accumulation, ghost rows of the gradient are zeroed (the forward output's ghost rows do not depend on ghost inputs). The kernels run on the device stream, the same pattern mliap/kk uses, so no explicit torch↔Kokkos fence is needed.

3.4 Multirank input build and model detection

preprocess_multirank() builds inputs in LAMMPS atom-index order (owned 0…nlocal−1, ghosts nlocal…ntotal−1) so tensor rows line up with what Comm expects; ghost positions are real coordinates, hence edge_cell_shift ≡ 0; edges come from local atoms only with real neighbor indices (no tag remap). Detection is automatic: coeff() checks whether the model declares num_local_ghost_atoms among its inputs; a metadata stamp written by nequip-compile is cross-checked against that, warning on disagreement (declared inputs win). Multi-rank models require newton pair on and get a clear error otherwise; single-rank models on N ranks get an error containing the exact recompile command.

3.5 Self-contained accelerated artifacts (OEQ)

Models using accelerated TP kernels reference custom ops that Python registers via import openequivariance — unavailable in C++. For pair_* targets, nequip-compile now embeds the actual .so binaries in the .pt2 zip (STORED, under nequip_custom_op_libs/), resolving them from the library's declared accessor with a /proc/self/maps fallback. The pair style extracts them with a ~100-line dependency-free ZIP central-directory reader and dlopen(RTLD_NOW | RTLD_GLOBAL)s them before loading the model. Overrides: a <model>.oplibs sidecar and NEQUIP_OP_LIBRARIES. This also fixes single-rank OEQ models in plain C++ LAMMPS, independent of multi-GPU.

3.6 Version-robust rebundle for pre-existing packaged models

A .nequip.zip carries frozen nn source and pickled instances whose __init__ never re-runs. A package predating this work would compile for the multirank target but silently skip truncation — the energy sum includes ghosts (observed in production as a +0.774 eV/atom offset before this machinery existed). The fix has two layers:

  • Auto-rebundle: compiling a stale package for the multirank target derives an era-matched overlay from the package's own bundled source and applies only bounded, additive grafts (nequip/scripts/_multirank_graft.py: marker branch, marker passthrough, exchange module, custom-ops metadata, owned-only reduce + ZBL). Deriving from the package's own source keeps its frozen instances attribute- and import-compatible by construction, for any nequip era — injecting the installed nn was demonstrated to crash on era mismatches (avg_num_neighbors_norm and friends). The rebundle runs through nequip-package update, which verifies predictions unchanged.
  • Gate: a LAMMPS-level correctness gate (single-rank reference vs multirank artifact at 1 rank with ghosts; PBC makes nghost > 0 so the exchange path actually runs) because the eager prediction-verify structurally cannot exercise it.

Maintainer question flagged in §7: whether auto-rebundle belongs upstream or should remain a deployment-side tool — models re-exported from checkpoints with a current nequip never need it.

4Compatibility: additions, not modifications

Every pre-existing feature is preserved. The multirank machinery activates only for models that declare the new input — impossible for any model compiled before this work. Each branch's UPSTREAM_DELTA.md enumerates every shared-path touch exhaustively; the full tables live there, summarized here.

pair_nequip_allegro (10 shared-path touches)

  • Comm-buffer sizing: nequip-compile stamps the widest per-node feature width crossing the exchange into the artifact (pair_nequip_feature_width), and coeff() sizes the LAMMPS comm buffers exactly from it. Non-multirank models (all pre-existing ones) get comm_forward = comm_reverse = 0 — exactly upstream's memory behavior. Only a multirank model compiled before the stamp existed falls back to a bounded default, guarded by a hard-error (never overflow) in the exchange.
  • The single-rank restriction moved from constructor to init_style() — required because multirank capability is only known after coeff(); same protection, actionable message.
  • AOT loader pins weights to the rank's device; each model call runs under a device guard — identity on one GPU, correctness fix on many (default left every rank's weights on cuda:0 → cross-device fault).
  • Force/energy write-back restructured to if (is_multirank) … else — the else branch is the upstream loop verbatim.
  • Second in-process AOT load (e.g. after clear): clean, explanatory error where a segfault used to be. Op-library loading no-ops when a model embeds nothing. Kokkos reverse_comm_device = 1 is inert for allegro/kk, which never issues pair-initiated reverse comm. Four commented-out debug lines removed.

nequip (6 shared-path touches)

  • AtomwiseReduce's owned-mask and batch-slice are provable no-ops on every existing path (ML-IAP already truncates its field before the reduce; without the key the branch is skipped).
  • InteractionBlock's slice was split into two statements — identical semantics; the new marker branch is an elif between the existing two.
  • Key-registry additions register the pre-existing ML-IAP ghost-count key as graph-typed for export machinery; exercised only by the new target.
  • The custom-ops embedding block now unions metadata with modifier-derived libs (warning when metadata was incomplete); name-based embedding for Python consumers unchanged.
  • One genuine upstream bug fix: ZBL's per-atom energy scatter used dim_size = nlocal in local-ghost contexts — an out-of-bounds write whenever an edge centers on a ghost atom (reachable via today's ML-IAP + ZBL). Fixed by scattering over ntotal then truncating; identical result in the no-ghost case. Separable as its own PR.

6.1.1 The ML-IAP baseline was tuned, not stock

The comparison is only meaningful if the ML-IAP route ran with its optimizations on. It did — the benchmarked mliap/kk configuration carried, verified against the wrapper source at the benchmark module's nequip commit and the container recipe:

  • OpenEquivariance kernels — the same enable_OpenEquivariance modifier as pair_nequip, so both engines execute identical accelerated tensor-product kernels. (The compute-bound parity in §6.4 is the direct evidence of kernel fairness.)
  • torch.compile, on by default in the ML-IAP wrapper, with freezing set so weight constant folding happens at compile time (the wrapper sets it via inductor config because the options= path doesn't take). Default inductor mode.
  • disable_ForceStressOutput — energy-only graph with forces through the ML-IAP edge-force route, the intended pattern for this integration.
  • Per-edge-type cutoff neighbor-list pruning (NeighborListPruneTransform) — the LAMMPS neighbor list is pruned to the model's per-pair cutoffs before the model sees it.
  • The ML-IAP ghost-exchange modifier — upstream's own multi-rank mechanism for this route, active in all multi-GCD runs.
  • Kokkos ML-IAP (pair_style mliap unified … -sf kk, newton on) with device-resident data and GPU-aware Cray MPICH (GTL) for the cross-rank exchange.
  • The torch↔Kokkos stream-race fix applied as a container source patch (two torch.cuda.synchronize() at the torch↔LAMMPS boundary, ~0.8% overhead; since merged upstream as nequip #605) — required to keep mliap/kk fault-free at all on MI250X, and included in every benchmarked run.
  • Same precision (fp64 I/O, fp32 inference) and the same CPU-binding masks as pair_nequip — the binding correction of §6.1 helped mliap far more than pair_nequip and is baked into every number on this page.

Deliberately not used, for the record: an earlier HIP-graph-capture variant of the mliap path (~90 ts/s in one experiment) was NVE-only and fragile and was dropped from the campaign before the head-to-head; an experimental max-autotune-no-cudagraphs compile mode exists only on a side branch (add-lammps-mliap-compile-mode) and was not in the frozen benchmark module — for either engine.

Methodology caveat that reshaped the results: the first scaling pass ran with --cpu-bind=none, which does not cost "a few percent" — ranks float across CCDs and stall at collectives (Other up to 57% of loop time, Comm %varavg 278%). The heavier-synchronization mliap path paid far more than pair_nequip, inflating early speedup claims. Every number below is from bound runs; unbound-vs-bound deltas are in the campaign record. Reviewers comparing engines on other machines should bind first.

7Proposed path to merge

  • PR 0 (small, independent): the ZBL local-ghost scatter fix to mir-group/nequip — self-contained correctness fix for the existing ML-IAP path.
  • PR 1: mir-group/nequip — the pair_nequip_multirank target, marker key, nn modules, .so embedding, and (pending the maintainer question) rebundle machinery. henriasv/nequip@pr/multigpu, rebased on current main.

Open questions for maintainers

  • Should auto-rebundle (§3.6) land upstream, or stay a deployment-side tool with docs pointing to re-export-from-checkpoint?
  • Naming review: pair_nequip_multirank (target), pair_style nequip/kk, and the pair_nequip_feature_width / pair_nequip_multirank metadata keys.
  • The slice_scatter export reasoning and marker-key design vs upstream's export-guard conventions.

Previously-open items now closed on the branches: exact comm-buffer sizing (stamped by the compiler, read by the pair style; non-multirank models restored to upstream's zero comm footprint), a CPU-runnable regression test (PairNequIPMultirankMixin in the standard pytest suite), a user-facing docs page (docs/integrations/lammps/multirank.md), and the ZBL fix carved out as the standalone branch fix/zbl-local-ghost-scatter ready for PR 0.
