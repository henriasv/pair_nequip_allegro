PR 0nequip — ZBL local-ghost scatter fix

Branch fix/zbl-local-ghost-scatter → mir-group/nequip main. One file, +10/−7, independent of everything else.

## Summary

`ZBL.forward` scatters per-edge energies into a per-atom buffer sized by the
per-atom energy field. In a local-ghost context (the LAMMPS ML-IAP integration
today) that field spans only the `nlocal` owned atoms, while `edge_center`
still indexes ghost atoms up to `ntotal` — so the scatter with
`dim_size=nlocal` is an out-of-bounds write whenever an edge is centered on a
ghost atom.

## Fix

Scatter over all `ntotal` nodes (positions are never truncated, so
`ntotal = positions.shape[0]`), then truncate the result to the owned count
before adding it to the per-atom energy field — the same
"compute-wide-then-truncate" pattern the conv stack uses
(`tp_scatter(...)` then `x[:num_local_nodes]`).

In the no-ghost case (`nlocal == ntotal`) the two formulations are identical,
which the existing test suite confirms.

## Testing

- Full unit suite passes, and results are bit-identical to `main` in the
  no-ghost paths.
- Found while building a multi-rank `pair_nequip` path (follow-up PR), where
  the local-ghost context made the OOB write reproducible.

PR 1nequip — the pair_nequip_multirank compile target

Branch pr/multigpu → mir-group/nequip main. +1134/−18 across 17 files (2 new modules, plus docs page and regression test), rebased on current main. Contains the PR 0 commit (rebase after PR 0 merges, or review together).

## Summary

Adds a `pair_nequip_multirank` AOTInductor compile target: models compiled
with it run LAMMPS-domain-decomposed across MPI ranks/GPUs with the
`pair_nequip` pair style (companion PR in `pair_nequip_allegro`). The compiled
model performs a per-layer ghost-feature exchange through a registered Torch
custom op; LAMMPS installs the real implementation at load time.

Two ideas make this exportable where the ML-IAP ghost exchange is eager-only:

1. **The exchange op carries no LAMMPS handle in its signature**
   (`nequip_lammps::ghost_exchange`, with its autograd transpose registered) —
   the pair style reaches the op through a thread-local bridge, and with no
   comm context the op is the identity (ASE / export tracing / single rank).
2. **Truncate-to-nlocal via a backed dynamic dim**: the owned-atom count
   enters the graph as the *shape* of a marker input, never via `.item()`, so
   per-node ops slice to owned atoms without unbacked-symint guard failures.
   Re-expansion before each exchange uses `slice_scatter` (not `cat`) to avoid
   0/1-size specialization.

## Also included

- Custom-op `.so` embedding for `pair_*` targets so accelerated artifacts
  (e.g. OpenEquivariance) are self-contained for a C++ consumer, plus a
  `pair_nequip_feature_width` metadata stamp for exact LAMMPS comm sizing.
- A version-robust auto-rebundle for packaged models predating this feature
  (derives an era-matched overlay from the package's own bundled `nn`;
  happy to split this out or keep it deployment-side — maintainer call).
- Docs page (`docs/integrations/lammps/multirank.md`) and a CPU regression
  test (`test_pair_nequip_multirank_matches_single_rank`: single-rank vs
  multirank artifacts must agree at `nghost = 0`, plus metadata asserts).

## Compatibility

Additions only: the new input/target/modifier cannot activate for any
existing model or workflow. Every touch of shared code is enumerated with a
verdict in `UPSTREAM_DELTA.md` at the branch root. Unit suite passes
identically to `main` in the same environment.

## Validation (LUMI-G MI250X, 1–32 GCDs, production OAM models)

Single-rank vs multi-rank PE exact at 1 rank; rank-invariance ~1e-6 eV/atom
across 1/8/32 GCDs; max |ΔF| ~1e-5 eV/Å; cross-engine agreement with
mliap/kk; ~2.2–2.6× higher strong-scaling throughput ceiling than mliap/kk
with identical OEQ kernels (parity when compute-bound, as expected).
Full evaluation document with benchmarks and environments:
https://henriasv.github.io/pair_nequip_allegro/

PR 2pair_nequip_allegro — multi-rank pair style

Branch pr/multigpu → mir-group/pair_nequip_allegro main. +792/−22 in the four pair-style sources only. Runtime-inert without a PR 1 model.

## Summary

Native multi-GPU `pair_style nequip` for models compiled with nequip's new
`pair_nequip_multirank` target (companion PR in `nequip`). The compiled model
calls `nequip_lammps::ghost_exchange` between layers; this PR registers the
real implementations and routes them through LAMMPS communication:

- **Plain pair**: host-staged halo via `Comm::forward_comm/reverse_comm` and
  the standard pair pack/unpack callbacks.
- **Kokkos** (`pair_style nequip/kk`, new instantiation): device-resident —
  pack/unpack kernels index the live feature tensor by the device sendlist,
  exchanged via `CommKokkos::*_comm_device` (GPU-aware MPI), reverse path
  accumulates with atomic adds and zeroes ghost-row gradients.
- Multi-rank input build in LAMMPS atom order (real ghost positions ⇒ zero
  `edge_cell_shift`, no tag remap), owned-only energy accounting, ghost
  forces home via standard Newton reverse comm (`newton on` required).
- Model capability is auto-detected from the declared inputs and
  cross-checked against compile metadata; comm buffers are sized exactly
  from the model's `pair_nequip_feature_width` stamp (non-multirank models
  keep upstream's zero comm footprint).
- Robustness: actionable error for a single-rank model on N ranks (includes
  the recompile command); a clean error instead of a segfault on a second
  in-process AOT model load (e.g. after `clear`); custom-op `.so` loading
  from the artifact for accelerated models (also fixes single-rank OEQ
  models in plain C++ LAMMPS).

## Compatibility

`is_multirank` can only become true for a model that declares the new input —
impossible for anything compiled before this feature. The upstream code paths
are preserved verbatim (force loop in an `else` branch); the few shared-path
touches are enumerated with verdicts in `UPSTREAM_DELTA.md` at the branch
root.

## Validation

Compiles on LUMI (hipcc, Kokkos/HIP gfx90a, C++20, LAMMPS patch_30Mar2026)
and CUDA; correctness gate (single-rank reference vs multirank artifact,
1 rank with ghosts) passes exactly; PE rank-invariant 1/8/32 GCDs to ~1e-6
eV/atom; benchmarks and environments:
https://henriasv.github.io/pair_nequip_allegro/
